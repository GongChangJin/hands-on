# GongChangJin Hands-on

새로운 기술을 직접 실행하고, 프로젝트에 사용할 수 있는지 짧은 호흡으로 검증하는 공간입니다.

각 실험은 하나의 명확한 질문에서 시작합니다. 단순한 사용법 복사보다 실제로 실행한 결과, 한계와 적용 판단을 남기는 것을 목표로 합니다.

## 실험 흐름

```text
planned → active → validated
              └──→ stopped
```

| 상태 | 의미 |
| --- | --- |
| `planned` | 질문과 실험 범위를 정함 |
| `active` | 직접 구현하고 확인하는 중 |
| `validated` | 결과와 프로젝트 적용 판단을 기록함 |
| `stopped` | 중단 이유와 현재까지의 결과를 기록함 |

## 실험 추가하기

1. `experiments/README.template.md`를 `experiments/<YYYY-MM-DD>-<topic>/README.md`로 복사합니다.
2. 해당 디렉터리 안에 실험 코드와 실행에 필요한 파일을 함께 둡니다.
3. 중첩된 Git 저장소를 만들지 않습니다.
4. 화요일·목요일 세션이 끝날 때 결과와 다음 행동을 갱신합니다.
5. 독립 실행·배포·제출이 필요한 수준으로 커지면 별도 프로젝트 레포로 승격합니다.

## 함께 실험하는 방법

실험은 참여자보다 **주제와 질문을 기준으로** 디렉터리를 만듭니다. 같은 기술이나 질문을 검증한다면 하나의 실험 디렉터리를 함께 사용하고, 참여자마다 구현 방식이 다를 때만 `implementations/<github-id>` 아래에 코드를 나눕니다.

```text
experiments/
└── 2026-09-08-agent-framework/
    ├── README.md
    ├── shared/                    # 공통 자료와 설정(필요한 경우)
    └── implementations/           # 각자 별도로 구현할 때만 생성
        ├── github-id-a/
        └── github-id-b/
```

- 실험의 공통 질문, 진행 상황, 구현 비교와 최종 결론은 실험 디렉터리의 `README.md`에 함께 기록합니다.
- 공통으로 사용하는 자료나 설정이 있다면 `shared/`에 둡니다.
- 같은 파일을 동시에 수정해야 한다면 각자 브랜치에서 작업한 뒤 합칩니다.
- 공용 `README.md`는 세션마다 정리 담당자를 정하면 수정 충돌을 줄일 수 있습니다.
- 참여자별 디렉터리를 최상위에 만들지 않습니다. 개인별 분리는 실험 내부에서 서로 다른 구현을 비교할 때만 사용합니다.

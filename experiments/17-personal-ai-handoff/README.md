# 17. Personal AI로 이어지는 소스 인계

학습 슬롯: **2026-10-30**. 현재 `personal-ai`의 소스와 요구사항을 돌아보며 구성한 후속 실험이다. 이 날짜는 실제 실험 수행일의 증거가 아니다. 실행 시각은 결과의 `evaluated_at`에 별도로 기록한다.

- 상태: `validated` — 로컬 구성요소 통합·소스 인계 계약 범위
- 참여자: `@ukkhnn`
- 선행: 10~16
- 후행: `personal-ai/agent-workspace` 제품 검증

## 왜 이 실험인가

01–09는 모델·검색·라우팅·도구·보안 기능을 비교했다. 통합 v1은 그 기능의 연결과 기본 안전 경계를 확인했다. 개인 AI 워크스페이스에는 그 위에 실행 엔진의 차이, 저장과 복구, 추가 지시, 승인, 설정·메모리, 독립 개발 폴더, 기기 전환이 필요하다. 10–16의 작은 실험을 한 흐름으로 연결하고, 어느 근거를 `personal-ai`에 가져갈 수 있는지 마지막으로 확인한다.

여기서 인계하는 것은 **Git 소스와 새 실행을 준비할 절차**다. 다른 컴퓨터로 살아 있는 세션을 옮기거나 자동으로 이어 실행하지 않는다. API 키, 접속 토큰, 실제 사용자 대화, 실행 폴더의 절대경로, 엔진 세션 ID는 인계 계획에 들어가지 않는다.

## 검증 범위

- 10의 실제 로컬 HTTP fixture와 16의 두 인증 클라이언트를 사용한다.
- 11–12의 저장·대기열, 13의 작업별 승인, 14의 템플릿·기억, 15의 임시 Git 저장소와 worktree를 합성한다.
- 실행 접수와 완료를 구분하고, 서버를 재시작해 기록·완료 상태·이벤트 커서를 확인한다.
- 완료 여부가 불확실하거나 대기 작업이 남으면 인계 계획을 만들지 않는다.
- 알려지지 않은 스키마·추가 필드·민감 파일·절대경로를 거부한다.
- 현재 `personal-ai` 소스의 revision과 파일 해시를 기록하고 구현된 범위와 남은 범위를 나눈다.

실제 모델 호출, 사용자 저장소 수정, 외부 push, Mac mini 배포, 모바일/Tailscale/HTTPS 연결은 수행하지 않는다. fixture가 파일을 생성했다는 사실을 AI가 코딩에 성공한 결과로 해석하지 않는다.

## 시작

```sh
cd implementations/ukkhnn
npm test
npm run evaluate
```

소스 기준점 재확인은 `npm run evaluate -- --reference-root /path/to/personal-ai`로 선택한다. 이 경로는 읽기 전용으로 사용하며 결과에 절대경로를 저장하지 않는다. 경로를 주지 않으면 기준점 검증은 `not_rechecked`로 남는다.

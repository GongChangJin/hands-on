## 알아볼 것

- Issue 분석→수정→테스트→재수정 루프의 안정성
- 저장소 탐색과 patch 범위를 제한하는 방법
- 테스트 품질과 Agent 성공 판정의 관계

## 실험 범위

### 해볼 것

- 테스트가 있는 샘플 저장소와 Issue 5개 이상 준비
- 개인 branch 또는 임시 worktree에서만 변경
- 기존 테스트, 신규 회귀 테스트, lint 결과 기록

### 하지 않을 것

- 보호 브랜치 직접 수정·force push·자동 merge
- 테스트가 없는 변경을 성공으로 판정
- 저장소의 비밀값을 모델 입력에 포함

## 실행 방법

공통 샘플 저장소와 Issue·정답 테스트는 `shared/`, 개인별 Agent 구현은 `implementations/<github-id>/`에서 관리합니다.

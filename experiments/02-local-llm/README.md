# 02. Local/Open-weight LLM

> 로컬 모델이 API 모델을 대체하거나 보완할 수 있는 작업 범위는 어디까지인가?

## 프로젝트 정의

- **상태:** `planned`
- **참여자:** `@ukkhnn`, `@us788`
- **역할:** Router가 선택할 수 있는 로컬 모델 백엔드와 성능 기준 제공
- **선행 프로젝트:** Agent Evaluation
- **후행 프로젝트:** LLM Router, 통합 시스템

## 배경과 목적

로컬 오픈웨이트 모델을 API 모델과 동일한 입력으로 비교하여 개인정보 보호, 비용, 속도와 운영 복잡도의 실제 장단점을 확인합니다. 모델 자체 학습보다 추론과 애플리케이션 연결에 집중합니다.

## 과제 명세

### 입력

- 공통 프롬프트와 평가 태스크
- 3B~8B급 instruct 모델
- API 모델 기준선
- 모델·양자화·context·기기 정보

### 필수 구현

- 로컬 모델 설치와 추론 실행
- 공통 LLM adapter를 통한 호출
- 텍스트 생성과 구조화 출력 비교
- 첫 토큰 시간, tokens/sec, 메모리와 실패 기록
- API 모델과 동일 태스크 비교

### 산출물

- 로컬 모델 adapter
- 모델별 성공률·속도·자원 비교표
- 실행 설정과 재현 방법
- 모델 라이선스와 적용 제약

### 포함 범위

- 양자화 모델 추론
- 단일 기기 기준 성능 비교
- 짧은 질의와 구조화 출력 태스크

### 제외 범위

- 모델 사전학습·파인튜닝
- 모델 가중치 Git 커밋
- 라이선스를 확인하지 않은 서비스 적용

## 권장 기술

- Ollama 우선
- Apple Silicon에서는 Metal 가속 사용
- 선택적으로 MLX 또는 vLLM 호환 환경 비교
- Python LLM adapter와 시스템 자원 측정 도구

현재 기본 실습 기기에서는 4-bit 3B~8B 모델과 작은 context부터 시작하고, Docker 등 다른 고부하 작업과 동시에 실행하지 않는 것을 권장합니다.

## 디렉터리 사용

- `shared/`: 공통 프롬프트, 기대 결과, 측정 규칙과 라이선스 체크리스트
- `implementations/ukkhnn/`: `ukkhnn`의 모델·실행기 조합
- `implementations/us788/`: `us788`의 모델·실행기 조합

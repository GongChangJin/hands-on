# 02. Local/Open-weight LLM

> 로컬 모델이 API 모델을 대체하거나 보완할 수 있는 작업 범위는 어디까지인가?

## 프로젝트 정의

- **상태:** `validated`
- **참여자:** `@ukkhnn`, `@us788`
- **역할:** Router가 선택할 수 있는 로컬 모델 백엔드와 성능 기준 제공
- **선행 프로젝트:** Agent Evaluation
- **후행 프로젝트:** LLM Router, 통합 시스템

## 배경과 목적

로컬 오픈웨이트 모델을 API 모델과 동일한 입력으로 비교하여 개인정보 보호, 비용, 속도와 운영 복잡도의 실제 장단점을 확인합니다. 모델 자체 학습보다 추론과 애플리케이션 연결에 집중합니다.

## 과제 명세

### 입력

- 공통 프롬프트와 평가 태스크
- 3B~8B급 instruct 모델
- API 모델 기준선
- 모델·양자화·context·기기 정보

### 필수 구현

- 로컬 모델 설치와 추론 실행
- 공통 LLM adapter를 통한 호출
- 텍스트 생성과 구조화 출력 비교
- 첫 토큰 시간, tokens/sec, 메모리와 실패 기록
- API 모델과 동일 태스크 비교

### 산출물

- 로컬 모델 adapter
- 모델별 성공률·속도·자원 비교표
- 실행 설정과 재현 방법
- 모델 라이선스와 적용 제약

### 포함 범위

- 양자화 모델 추론
- 단일 기기 기준 성능 비교
- 짧은 질의와 구조화 출력 태스크

### 제외 범위

- 모델 사전학습·파인튜닝
- 모델 가중치 Git 커밋
- 라이선스를 확인하지 않은 서비스 적용

## 권장 기술

- Ollama 우선
- Apple Silicon에서는 Metal 가속 사용
- 선택적으로 MLX 또는 vLLM 호환 환경 비교
- Python LLM adapter와 시스템 자원 측정 도구

현재 기본 실습 기기에서는 4-bit 3B~8B 모델과 작은 context부터 시작하고, Docker 등 다른 고부하 작업과 동시에 실행하지 않는 것을 권장합니다.

## 결과

`@ukkhnn` 구현은 분류·추출·짧은 질의 각 8개, 총 24개를 두 모델에 3회씩 실행했다.

| model | 성공 | JSON schema | latency p50 / p95 | 첫 토큰 p50 | 안전 위반 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Qwen2.5 3.1B Q4_K_M | 60/72 (83.3%) | 72/72 | 370 / 757ms | 179ms | 0 |
| Qwen2.5 7.6B Q4_K_M | 69/72 (95.8%) | 72/72 | 574 / 1,241ms | 336ms | 0 |
| Solar Pro 4 API | 72/72 (100%) | 72/72 | 521 / 955ms | 미측정 | 0 |

7.6B는 분류·추출을 모두 통과했으나 기본 산술 한 건을 세 반복 모두 틀렸다. 3B는 혼합 감정, 산술 두 건, 논리 한 건을 세 반복 모두 틀렸다. 유효한 JSON 안의 의미 오류였기 때문에 schema와 정답을 분리한 판정이 필요했다.

Solar Pro 4 API는 실제 usage 14,688 token에서 전체 72회 추정 비용 $0.001582였다. 로컬 7.6B는 API 대비 정확도가 4.2%p 낮고 p50은 53ms 느렸으며, 3B는 16.7%p 낮지만 p50은 151ms 빨랐다. 로컬 호출비 0달러에는 장비·전력·운영비가 포함되지 않는다.

## 결론

- **적용 판단:** `trial` (7.6B 로컬 경로), 프로젝트 상태 `validated`
- **판단 이유:** 7.6B는 schema 100%, 전체 95.8%였고 4.8GB loaded memory로 현재 기기에서 충분히 실행됐다. 계산 오류가 반복돼 일반 질의 기본 경로로는 부족하다.
- **적용 가능 범위:** 저위험 분류·추출. 계산·논리는 결정적 도구 또는 상위 모델 fallback이 필요하다.
- **라이선스 경계:** 3B는 Qwen Research License라 비상업 연구·평가에 한정한다. 7B는 Apache 2.0 후보로 사용한다.
- **다음 행동:** 06 Router에서 분류·추출은 7.6B 로컬 후보, 계산·논리는 calculator 또는 API fallback으로 연결

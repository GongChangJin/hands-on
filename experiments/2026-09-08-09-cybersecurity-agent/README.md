## 실험 범위

### 해볼 것

- 의도적으로 만든 로컬 취약 저장소만 사용
- Semgrep 등으로 탐지→수정→테스트→재검사
- Docker의 CPU·메모리·네트워크·파일 접근 제한

### 하지 않을 것

- 외부 시스템 스캔·공격·취약점 악용
- `--privileged` 또는 Docker socket 전달
- 검사와 테스트를 통과하지 않은 수정을 성공으로 판정

## 실행 방법

취약 샘플과 예상 finding·보안 테스트는 `shared/`, 개인별 수정 Agent는 `implementations/<github-id>/`에 둡니다.
